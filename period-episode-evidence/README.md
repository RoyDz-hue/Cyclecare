# Period pair and episode storage decision ownership

Actual shared PeriodDateConsistency.validatePair (including repository caller)
and onboarding PeriodEpisodeEntry.decide are native-first with complete explicit
Kotlin fallback. Rust owns required/chronology/future error priority, inclusive
duration narrowed to Int before >7, exact ended/ongoing guidance, valid raw-end
selection and unusual/current-typical-vs-typical-duration storage decision.
JVM retains LocalDate parsing/epoch primitives and restores the original raw end
object rather than accepting any native date. LocalDate full epoch bounds are
strictly checked; full year domain and Int wrap are deliberately preserved even
when counterintuitive. No guidance, threshold, user date or estimate is rewritten.

Strict5-field input, exact versioned typed result and coherence decoding with
whole fallback; no silent defaults. Three direct-native host methods assert
nonnull JNI before independent pair/storage oracles and actual shared callers,
with full Java date extremes, error priority, thresholds, both messages, generated
corpus and schema/type/domain/unavailable failures. Original period and repository
boundary tests remain unchanged. Original pair oracle is name-only renamed;
storage oracle calls that explicit original pair oracle, avoiding nested-native
oracle contamination. Production VM/persistence/confirmation/effects unchanged.

Payload contains nullable epoch dates, today, ongoing and current typical duration.
These health values can be sensitive, but stay in-process with no new remote or
storage effect. This is decision ownership, not whole onboarding/repository/UI or
storage execution migration. Existing Compose design remains; UI/state/effects,
ABI/release/minifier/full-flow qualification and device runtime remain broader work.
No cloud, real records, production flag, release key, money or distribution.
